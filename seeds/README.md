# 种子信（海边邮局）

「海边邮局」是这个世界里的一个固定角色，不是一个真人。它寄出的信叫**种子信**：
用来在还没人写信的时候，让海面不至于空着，也让新来的人先摸到一点这个世界的形状。

**这个仓库里只放了一封模板**（`example.json.template`），没有任何正式内容。
正式的信属于运营者的写作，不属于这个服务端。

---

## 文件格式

一个文件一封，放在这个目录下，扩展名 `.json`：

```json
{
  "id": "001-some-slug",
  "topic": "一句不超过 16 个字的主题",
  "signature": "可选，落款，最多 40 字",
  "body": "正文，最多 400 字"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定标识。去重、日志、接口都按它认信。**改 id 等于换了一封新信** |
| `topic` | 是 | 只做展示用的一行标签，不参与投递匹配 |
| `body` | 是 | 正文。上限 400 字（比桌宠写的 120 字宽松，因为是手写的） |
| `signature` | 否 | 落款，显示在正文下面 |

以 `.` 开头的文件和不是 `.json` 结尾的文件会被忽略——所以模板叫 `example.json.template`，
**不改名就永远不会被当成真信加载**。

想让模板生效：`cp example.json.template 001-my-first-letter.json`，然后改内容。

---

## 三条写作规矩

这三条不是文风偏好，是这个角色成立的底线。

1. **不伪装成任何一个真人。** 来源永远显示「海边邮局」。这是真实身份标注，不是可选项。
2. **永不回信。** 邮局是单向的。收信人只能「收好」，页面不给回信按钮——
   留一个点了石沉大海的按钮，等于骗人。
3. **每封独立，不连载。** 不写「上回说到」，不假定读者认识任何角色。
   捞到一封是完整的一件小事；捞到很多封，才慢慢认出同一个港口、同一群人和同一条暗线。

第三条尤其重要：种子信是**拼图**。每一块单独成立，合起来才显出全貌。

## 怎么加

1. 写一个新文件，`id` 别和已有的重复。
2. 放进这个目录。服务端**热载**，几秒内生效，**不用重启**（重启会清空海面上还漂着的信，
   所以改种子这件事绝对不能重启）。
3. 用 `/health` 确认：

```bash
curl -s localhost:8787/health | jq '.seeds | {count, generation, errors}'
```

- `generation` 变大 → 热载成功
- `errors` 非空 → 有文件没通过校验，被跳过了，旧版本仍在使用

生产环境建议把种子目录做成一个**私有** git 仓库，服务器定时 `git pull --ff-only`。
私有是因为：种子是给用户看的内容，提前公开就等于剧透。

---

## 建议：只加，不改

改一封已经被人领过的种子，会让那个人下次看到不一样的内容（正文从文件读，状态在库里）。
技术上可以，但语义上是在改一封已经寄出去的信。**建议只加新文件。**
